# T15a — Images: proxy, post images, card toggle — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first image on screen — post images on cards and above the post title, served
through a signed image proxy, with a *Post cards: Image / Compact* setting that picks the card
version.

**Architecture:** An `imgproxy` container beside `api` resizes and crops originals on demand and
stores nothing (stage 1 of three). Django signs a URL per width in `core/images.py` — the only
module that knows how such a URL is made, pinned by a containment test — and `PostSchema` carries
ready `<img>` attributes (`image: {src, srcset} | null`) in place of the raw `image_url`. The
frontend puts those attributes in a tag and never builds a URL.

**Tech Stack:** Django 5.2 + django-ninja + Docker Compose (`ghcr.io/imgproxy/imgproxy` v3);
Nuxt 4 + Vue 3 + TypeScript, plain `<img srcset>` — no `@nuxt/image`, no client-side signing.

**Spec:** [docs/images.md](../../docs/images.md) (strategy, wire contract, sizes, rendering
rules) and [docs/backend-roadmap.md](../../docs/backend-roadmap.md) § T15a (what to build).
Both travel with this plan; where this plan and the spec disagree, the spec wins — except for
the two deviations recorded under Global Constraints, which were agreed on 2026-09-22.

---

## Global Constraints

- **The frontend never builds an image URL.** `core/images.py` is the only module that reads an
  `IMGPROXY_*` setting; a containment test fails the suite if another `core/**` module does.
- **Sizes:** `WIDTHS = (480, 960, 1440, 1920)`, `DEFAULT_WIDTH = 960`, 16:9 fill, centre gravity,
  `.webp` named in the URL, never negotiated.
- **An empty `IMGPROXY_KEY` is a supported state**, exactly like `YOUTUBE_API_KEY`: every `image`
  on the wire is `null` and every card renders compact.
- **`image_url` is renamed to `image` on the wire**, not reused with a new meaning. The database
  column `Post.image_url` does not change.
- **`PUT /settings` stays a full replace** — after this task it has four required fields, so the
  backend and the frontend store change inside the same task (Task 3) or the running app 422s.
- Backend: migrations are generated inside the `api` container, never hand-written. Tests are
  written with the task, run as `docker compose exec -T api pytest -q`. ruff's F401 deletes an
  unused import on save — put an import and its first use in the same edit.
- Frontend: `<script setup lang="ts">` then `<template>`, **no `<style>` block**, no imports for
  components/stores/utils (Nuxt auto-imports), tokens only — `bg-muted`, `rounded-xl`,
  `aspect-video`, spacing from the six-name scale. Never hand-format; the hook runs `eslint --fix`.
- **Deviation 1 (agreed 2026-09-22):** the mock *Cards* section at the top of
  `settings/Appearance.vue` ("Card style: Detailed", "Font size: 100%", "Mock content for now")
  is **replaced** by the real *Post cards* control, and the Font size mock row is deleted. It
  promises a feature nothing implements; T15a is the occasion to stop promising it.
- **Deviation 2 (agreed 2026-09-22):** the dev fallback key and salt are real hex values
  committed in `docker-compose.yml`. They are a dev convenience, not a secret — production sets
  `IMGPROXY_KEY` / `IMGPROXY_SALT` through `.env`, which is hook-guarded and git-ignored.

- [ ] **Step 9: Write `backend/core/images.py`**

```python
"""Signed image URLs — the one module that knows how an image URL is made.

docs/images.md § The one rule. The frontend never builds one (the URLs are signed, and a key
on the client is a key in the bundle), and on this side nothing else reads an IMGPROXY_*
setting — a containment test in tests/test_images.py enforces it, the way test_search.py pins
the tsvector to core/search.py. That containment is what makes this the upgrade seam: stage 2
(originals in a bucket) and stage 3 (a CDN, then a paid transformer) are changes inside this
file, with the wire contract and every component untouched.
"""

import base64
import hashlib
import hmac

from django.conf import settings

# One 16:9 family for cards and the hero (docs/images.md § Sizes and formats): 480 covers a 1x
# phone, 960 a 2x phone and a 1x desktop pane, 1440 a 3x phone and a 2x pane, 1920 a 2x reading
# measure. imgproxy never enlarges, so asking for a width the source can't fill costs nothing.
WIDTHS = (480, 960, 1440, 1920)
# the bare `src`, for an <img> that ignores srcset
DEFAULT_WIDTH = 960


def post_image(url):
    """Ready `<img>` attributes for a post image, or None when there is nothing to show.

    None for the 63% of posts whose `image_url` is blank, and for a deployment with no key —
    a supported state, like YOUTUBE_API_KEY: the app renders compact cards and nothing breaks.
    """
    if not url or not settings.IMGPROXY_KEY:
        return None
    urls = {width: _signed(url, width) for width in WIDTHS}
    return {
        'src': urls[DEFAULT_WIDTH],
        # the finished attribute, not a list of widths: the sizes are the backend's fact, and
        # sending them as data would let the two sides drift (docs/images.md § Wire contract)
        'srcset': ', '.join(f'{signed} {width}w' for width, signed in urls.items()),
    }


def _signed(url, width):
    # fill + centre gravity: predictable, and it takes exactly the black bars off YouTube's
    # 480x360 hqdefault poster. .webp is named in the path rather than negotiated from Accept,
    # so one URL is one file and no CDN has a Vary header to get wrong.
    path = f'/rs:fill:{width}:{round(width * 9 / 16)}/g:ce/{_b64(url.encode())}.webp'
    stamp = hmac.new(
        bytes.fromhex(settings.IMGPROXY_KEY),
        bytes.fromhex(settings.IMGPROXY_SALT) + path.encode(),
        hashlib.sha256,
    ).digest()
    return f'{settings.IMGPROXY_PUBLIC_URL}/{_b64(stamp)}{path}'


def _b64(raw):
    # unpadded base64url, both for the source URL and the signature — imgproxy's own encoding
    return base64.urlsafe_b64encode(raw).rstrip(b'=').decode()
```

the real-app pass in Task 5).

```vue
<script setup lang="ts">
import type { PostImage } from '~/assets/types'

// The 16:9 box a post image renders in — on a card, and above the post title.
// docs/images.md § Rendering: the box is sized before the image arrives so
// nothing shifts, and anything that can't fill it removes it rather than
// leaving a grey square or a broken-image icon behind.
const props = defineProps<{
  image: PostImage
  // what only the host knows: how wide the slot is
  sizes: string
  eager?: boolean
}>()

const hidden = ref(false)

// A blown-up thumbnail reads worse than no image: a tracking pixel or a 140px
// Reddit thumb is hidden instead. imgproxy never enlarges, so a small source
// arrives at its own size and this is how we find out. From stage 2 (T15d) the
// server knows the dimensions and answers null, and this stops happening.
const MIN_WIDTH = 320

function measure(event: Event) {
  hidden.value = (event.target as HTMLImageElement).naturalWidth < MIN_WIDTH
}

// The desktop post pane keeps one instance across posts, so a box hidden for
// one post would stay hidden for the next.
watch(() => props.image.src, () => { hidden.value = false })
</script>

<template>
  <div
    v-if="!hidden"
    class="aspect-video overflow-hidden rounded-xl bg-muted"
  >
    <img
      :src="image.src"
      :srcset="image.srcset"
      :sizes="sizes"
      alt=""
      :loading="eager ? 'eager' : 'lazy'"
      :fetchpriority="eager ? 'high' : undefined"
      class="size-full object-cover"
      @load="measure"
      @error="hidden = true"
    >
  </div>
</template>
```
